## 3. 모듈 시스템

워크플로우(API 형식)만 넣으면 자동 인식하고, `manifest.json` 값이 있으면 덮어씀.

- **프롬프트**: `PROMPT_HERE` 또는 인코더에서 Switch 노드를 따라가 실제 사용 중인 텍스트 입력 추적
- **두 번째 프롬프트(영상 모션)**: `PROMPT2_HERE` 또는 두 번째 비네거티브 인코더 소스
- **시드 / 해상도 / 참조 이미지(LoadImage, 제목으로 라벨) / LoRA / 고급 파라미터** 자동 탐지
- 영상 출력 노드(SaveVideo 등)가 있으면 영상 모듈 → 항상 [영상 생성] 탭
- 영상 워크플로우 안에 이미지 저장 노드가 있으면 **키프레임 단계**로 인식
- 가져오기 시 LLM 노드 제거, 빈 참조 슬롯(1번 제외)은 실행 시 워크플로우에서 제거
- 모듈 파일이 바뀌면 **재시작 없이 자동 재로딩** (수정 시각 비교)
- 작업 생성 시점의 모듈을 **스냅샷**으로 고정 (도중에 파일이 바뀌어도 섞이지 않음)

### 현재 설치된 모듈 (6개)

| ID | 이름 | 탭 | 비고 |
|---|---|---|---|
| `qwen_t2i` | Qwen Image 2.1 · 텍스트→이미지 | 이미지 | |
| `qwen_edit` | Qwen Image Edit 2.1 · 레퍼런스 편집 | 이미지 | 참조 2장, 크기 스위치 자동 ON |
| `ltx25_t2v` | LTX-2.5 · 텍스트→영상 | 영상 | 오디오 포함 |
| `ltx25_i2v` | LTX-2.5 · 이미지→영상 | 영상 | "이 컷으로 영상 만들기" 연결 대상 |
| `ltx25_flf2v` | LTX-2.5 · 첫/끝 프레임→영상 | 영상 | 컷 이어붙이기용 |
| `elements_video` | Elements → 영상 (Qwen 키프레임 + LTX-2.5) | 영상 | 참조 10장, 키프레임 게이트 |

- qwen_edit / ltx25_i2v / ltx25_flf2v / elements_video는 **ComfyUI 실제 프런트엔드(같은 버전)를 컨테이너에서 띄워 UI→API 변환**하고, 같은 버전 검증기로 구조 검증 후 배치함.
- Elements 워크플로우: Qwen 키프레임 → `SplitImageWithAlpha`(RGBA→RGB) → LTX I2V. (Qwen 2.1 VAE가 4채널을 출력해 LTXV Preprocess가 실패하던 문제 해결)

## 4. 생성 파이프라인 (한 장 기준)

```
① 프롬프트 확장 (LLM)  ─ 참조 있음: image N 번호 지시문 / 없음: 일반 T2I 프롬프트
② (영상) 모션 프롬프트 확장 1회
③ VRAM 교대: LM Studio 모델 언로드 → ComfyUI 생성
   └ Elements: [키프레임만 생성 → 키프레임 검수] → 통과 시 키프레임을 LoadImage로 넣고 영상 부분만 실행
④ 규칙 검수 (거의 단색 여부 · 해상도 차이는 탈락 아님, 메모만)
⑤ LLM Vision 검수 → {score, defects, reason}
⑥ 통과 → _passed / 실패 → 재시도 전략 → 최대 횟수 후 최고점 컷을 _failed (+사유 .txt)
```

### 결함 코드 (8)
`off_brief` 기획 불일치 · `product_distortion` 제품 변형 · `anatomy` 인체 파손 · `text_artifact` 깨진 글자 · `low_quality` 저품질 · `composition` 구도 · `brand_tone` 톤앤매너 · `motion_artifact` 영상 변형(영상만)

### 재시도 전략
| 상황 | 전략 |
|---|---|
| off_brief / brand_tone / text_artifact | 검수 사유를 넣어 프롬프트 재작성 + 새 시드 |
| 참조 이미지 + text_artifact (라벨 깨짐) | 제품 크게·정면 지시 + 키프레임 해상도 ×1.25 + 새 시드 |
| 그 외 | 같은 프롬프트, 새 시드 |
| Elements: 키프레임 통과·영상만 실패 (글자·모션·저품질) | 키프레임 유지, 영상만 새 시드 |

### 검수 기준 메모
- 영상: 해상도·움직임 때문에 작은 글씨가 흐린 건 결함 아님. 크게 보이는 글자가 엉뚱하게 바뀐 경우만 실패.
- 참조 기반: 실제 제품 라벨과 다른·뒤섞인 문구는 실패, 너무 작아 안 읽히는 건 OK.
- LLM이 JSON을 못 지키면: 프롬프트 확장은 "문장만" 재요청, 검수는 `SCORE/DEFECTS/REASON` 3줄 형식으로 재요청.

## 5. UI 주요 기능

- **탭 분리**: 이미지 생성 / 영상 생성 — 탭별로 폼·모듈·작업 피드 독립. 서버도 탭과 모듈 종류가 다르면 거절.
- **참조 이미지**: 작은 5×2 슬롯, 드래그&드롭·여러 장 추가, 칸 번호 = 프롬프트의 image 번호
- **LoRA**: 적용 대상 모델 표시(예: Qwen Image · 키프레임 단계), 호환 묶음별 목록(다른 모델용은 선택 불가), 모듈별 마지막 LoRA·강도 자동 기억
- **비율·해상도**: 비율 칩 + 해상도 단계 (영상 480p/540p/720p·1K/2K/3K/4K, 이미지 1K~4K). 키프레임·LTX Resolution Selector에 동시 반영
- **영상 길이**: 모델별 범위 (LTX 3/5/8/10초, Wan 2~5초) + 예상 생성 시간·VRAM 초과 경고
- **확장 프롬프트 미리보기**: 기획 문장·모듈이 바뀌면 자동으로 "사용 안 함" 처리
- **작업 카드**: 단계 표시(① 키프레임 → 검수 → ② 영상), 시도별 썸네일, 재시도 전략 표시, ✕ 버튼으로 **결과 파일+기록 삭제**
- **모듈 가져오기**: ComfyUI 최근 실행에서 바로 가져오기, 모델 기반 ID·이름·종류 추천, 다른 모델 덮어쓰기 경고
- 갤러리(이미지/영상 필터·결함 필터), 기록·통계, 사람 채택/반려 라벨(검수 신뢰도 계산용), 모델 다운로드 관리자

## 6. 주요 결정 사항과 이유

| 결정 | 이유 |
|---|---|
| ComfyUI Desktop + LM Studio 로컬 구성 | 비용 0, 재현성, 포트폴리오 데모가 오프라인에서도 동작 |
| VRAM 교대(LLM 언로드 ↔ ComfyUI /free) | 12GB 한 장으로 26B LLM과 22B 영상 모델을 번갈아 사용 |
| LLM 호출 직렬화 + json_schema + 재시도 | 동시 호출 시 "Model unloaded"·미검수 발생 → 해결 |
| 모듈 = 워크플로우 파일 + 자동 인식 | 노드 편집은 ComfyUI에서, 앱은 파라미터만 제어 (역할 분리) |
| Elements는 키프레임 먼저 검수 | 라벨 깨진 키프레임으로 3~5분짜리 영상을 만드는 낭비 제거 |
| 일관성은 이미지(키프레임) 단계에서 고정, 영상은 모션 담당 | LTX-2.5 22B LoRA 학습은 12GB로 불가 → 제품 LoRA는 Qwen 단계에 |
| 해상도 불일치는 탈락이 아닌 메모 | 설정 문제를 품질 결함으로 오판하던 문제 |
| 영상 기본 최대 시도 3회 | 키프레임 재시도는 비용이 작음 |
| 작업 삭제는 출력 폴더 안·작업 전용 폴더만 | 안전 (휴지통 없이 영구 삭제라 확인창 필수) |

## 7. 해결한 문제 기록 (2026-10-11)

1. 가져오기 창이 항상 `qwen_t2i`를 기본 ID로 써서 LTX가 Qwen 모듈을 덮어씀 → 모델 기반 추천 + 덮어쓰기 경고, 원래 모듈 복구
2. 서버가 모듈을 시작 때만 읽어서 이미지 탭에서 영상이 생성됨 → 자동 재로딩 + 탭/종류 검증 + 작업별 스냅샷
3. Elements에서 `LTXVPreprocess: (856,1536,4)` 오류 → RGBA→RGB 노드 삽입
4. 다른 모델용 LoRA(minimax)가 Qwen에 걸림 → 호환 판별·자동 선택
5. 라벨 글자 깨짐으로 반복 실패 → 레퍼런스 전용 프롬프트·키프레임 게이트·라벨 재시도 전략
6. Qwen Edit 결과가 참조 이미지 크기로 나와 전부 "해상도 불일치" → 크기 스위치 자동 ON + 규칙 완화
7. 예전 확장 프롬프트가 남아 엉뚱한 이미지 생성 → 기준(문장+모듈) 추적
8. Gemma가 JSON 대신 분석 메모를 반환 → 텍스트/3줄 형식 폴백

## 10. LoRA 고도화 아이디어 (참고: 조피디 "ComfyUI 완벽 가이드 Part.4 로라 사용법 + Concept Slider LoRA")

영상 요점: LoRA는 model/clip 강도를 따로 가짐, 같은 시드 고정 후 적용 전/후 비교, Concept Slider LoRA(나이·표정·피부톤)는 **음수~양수 가중치**로 구도는 유지한 채 속성만 조절, 여러 LoRA를 체인으로 연결, 값 변경 시 자동 재생성.

우리 툴에 적용할 것 (판단):
| 기능 | 판단 | 메모 |
|---|---|---|
| **LoRA 강도 자동 탐색** (같은 시드로 0.4/0.6/0.8/1.0 → 검수 점수 최고값 채택) | ◎ 최우선 | 자동 검수가 있는 우리 툴만의 차별점. "가중치를 감이 아닌 데이터로 결정" |
| **적용 전/후 비교 생성** (시드 고정, LoRA on/off 나란히) | ◎ | 포트폴리오 "LoRA 효과 검증" 근거 자료로 바로 사용 |
| **LoRA 여러 개 스택 + 개별 가중치(음수 허용)** | ○ | 제품 LoRA + 디테일/조명 LoRA 조합. 슬라이더류는 SD1.5/SDXL용이 많아 Qwen/LTX 호환 확인 필요 |
| model/clip 강도 분리 | △ | Qwen·LTX LoRA는 대부분 model-only 로더라 효용 낮음 |
| 값 변경 시 자동 재생성 (Auto Queue) | △ | 3080에서 장당 1~2분이라 실시간성 낮음 — 저해상도 미리보기로만 고려 |
